# Plan — Session 144

## Contexte technique
Swift 6, AppKit, TOMLKit existant ; aucune dépendance ajoutée. macOS 14+. MainActor pour les gestes et l’état d’animation ; writer AX existant hors fil principal. Build et installation par scripts/test, scripts/install, scripts/roadiedctl.

## Réutilisation et architecture
1. Étendre EffectsConfig avec animations et drop_preview. Étendre le catalogue et SettingsOrganization ; page Effets. Configuration par action, profils prédéfinis, validation bornée. L’aperçu réel reste indépendant de l’activation des animations et de live_drag_preview.
2. Ajouter Motion (calcul pur, RoadieCore), partagé par au moins quatre consommateurs réels : rail, overview, panneaux, frames AX. Courbes temporelles et ressort à état/vitesse ; temps monotone. Un ordonnanceur MainActor commun ne tourne que pour ses transitions actives. Dernière cible seulement. Annulation d’un identifiant sans affecter les autres.
3. Étendre LiveDropPreview plutôt que créer une autre session : source incluse uniquement si begin a déclaré un geste possédé ; restaurer aussi la source. Quand live_drag_preview=false, seules les commandes source restent admises. La session garde le même contexte, permis, dispatcher, contrôle de scope et fin différée. En mode réel le contour est retiré ; refus de taille et absence de propriété sont explicites.
4. Étendre WindowDragReorderController et RailController par un tap souris limité au mode réel. Le clic initial traverse. La capture intervient avant le premier mouvement transmis ; pas d’AX dans le tap. Admissibilité sémantique préparée hors callback, contrôles/tabs exclus, sinon conserver le natif. Mouvements reçus directement par le contrôleur existant, sans moniteur doublé. Au relâchement, transmettre à AppKit le point initial afin qu’il ne rejoue pas le delta ; Roadie garde le point physique pour le dépôt. Échap termine et restaure ; conserver le drainage jusqu’au relâchement. Les glissers du rail sont déjà possédés.
5. Ajouter FrameTransitionRuntime : adaptateur asynchrone du dispatcher existant, sans second writer. SnapshotService.apply conserve son résultat immédiat quand les effets sont désactivés ou appel non pris en charge. Pour une animation réellement planifiée, le résultat porte explicitement deferred (aucun succès ou refus final inventé). Les consommateurs de résultats ignorent deferred dans les refus/réparations. La publication des frames réelles et le contrôle final restent sur le chemin commun ; les étapes intermédiaires sont hors budget final et révocables. Relever les callsites qui interprètent changed/attempted. Un maintien borné spécifique au runtime empêche le tick ordinaire de concurrencer l’animation. Une nouvelle commande ou un clic invalide les étapes anciennes ; les générations externes gagnent.
6. Rail : remplacer NSAnimationContext par le mouvement commun, conserver animation_ms comme valeur héritée. Overview : supprimer le cubic/150ms codé en dur et utiliser la politique commune. Panneaux lanceur/sélecteur/overview : fondu d’apparition/disparition sans retarder la restitution du clavier, panneau non interactif pendant sa sortie. Une présentation pendant sortie remplace celle-ci. Déplacement et changement de stage : appeler l’adaptateur de frames, sans photos ni nouvelles permissions.
7. Prévisualisation des réglages : une tuile locale utilise le même mouvement. Aucun effet sur les fenêtres ouvertes. Les réglages d’effets n’invalident pas la géométrie du tiler.

## Expérience de propriété du geste
Prototype signé, lancé par LaunchServices avec l’identité de développement existante ; aucune permission modifiée. La fenêtre fictive a été stabilisée pendant une seconde sur validation144 avant clic. Tap et AX autorisés dans ce lancement (le lancement terminal était refusé). Capturer les dragged empêche la reprise native ; neutraliser le delta du mouseUp évite le dernier saut. Frame réelle 450×800 et texte réorganisé vérifiés pendant l’appui. La reprise du tiler après relâchement est attendue dans ce prototype sans commande de dépôt. Reste à vérifier la qualification sémantique sur applications tierces pendant implémentation ; le chemin non admissible garde le contour.

## Complexité, coût et maintenabilité
O(k) calcul/état par image ; file bornée O(p+k), p applications. Cadence 30 Hz maximum pour AX, 60 Hz pour les panneaux. Le rendu réel sollicite l’application ; pas de copie CPU de pixels. Pas de capture supplémentaire. Animation bornée à 1 s, restauration et invalidation ≤500 ms hors appel AX déjà engagé. Un AX lent ne bloque pas les autres PID. Le futur mainteneur dispose de tests purs (courbes), doubles writer (sessions/annulation), matrice native et reçu de livraison. Aucun framework de plugins ni abstraction générique de backend.
