Cette observation ne prouve pas encore que les Spaces sont seuls responsables : le titre reçoit encore le mouseDown initial. Outil Sequential Thinking non exposé dans le catalogue ; raisonnement comparatif consigné ici avant code. Les anciennes sources et captures du prototype144 sont réutilisées. Pas de nouvelle dépendance ni nouvelle permission.

## Résultat du prototype isolé
Roadie suspendu uniquement pendant les comparaisons, puis relancé par scripts/roadiedctl start (santé vérifiée). Fenêtres fictives AppKit A/B/C. Préparation explicite des cadres et vérification de source visible dans les bornes réelles ; deux premières mesures sur une source masquée/parkée sont exclues.
Sans mouseDown livré à l’application : source réelle visible, Space cible3, cadre480×650 stable. En laissant le glisser natif ouvert : cadre cible temporaire mais Space source482 ; un mouvement ultérieur peut déplacer encore la source. Un mouseUp seulement postToPid termine ce mouvement AppKit mais laisse Space482 et contenu masqué. Un mouseUp ciblé dans le flux session, marqué pour le distinguer du relâchement physique : Space cible3, cadre480×650 visible, stable et restauré avant la vraie levée du bouton. Captures de région vérifiées : vraie fenêtreC et texte, pas une image étirée.
Le relâchement interne remet à0 les états NSEvent/CG combiné/HID même pendant l’appui simulé BTT ; le propriétaire doit donc conserver sa propre phase jusqu’au vrai mouseUp. Ne pas se fier à ces compteurs pour finir ce geste. Le filtre d’événement marqué et le maintien partagé interprocessus sont nécessaires. Le pont privé SLS testé sur la seule fenêtre fictive était indisponible (symbole/classe), aucun transfert privé exécuté ; solution retenue publique CGEvent.
Preuves brutes : /private/tmp/roadie145/session_up-title-result.json, session_up-title-region.png, session_up-title-samples.json. Ces essais utilisent BTT : le parcours manuel réel devra compléter la validation.

## Effet de bord du masquage animé
L’animation de masquage décalait de40points vers la gauche même une fenêtre déjà au parking x5351. Le pixel restant peut rendre isOnScreen=true. Les événements window_manual_display_move_adopted ont montré deux adoptions involontaires après démarrage. Le test a échoué sur les écritures intermédiaires avant correction ; il passe après suppression de cette excursion pour un masque déjà atteint/caché. Deux membres ont été remis par stage summon dans leur scope initial (écran interne, bureau1, stage8), sans fermer les applications ni restaurer le magasin global.
