# Cinq passages et limites de couverture

1. **Entrées et sécurité.** Socket local, installation et retrait de workflows, sources de scripts, recherches de secrets et dépendances. Le remplacement par `.` ou `..` a été reproduit et corrigé. Contre-audit indépendant par lecture.
2. **Données et calculs.** Plist, codes clavier, calculatrice et classement. Des conversions et une profondeur excessives ont été reproduites dans des sous-processus séparés ; des bornes et des tests ont été ajoutés.
3. **Concurrence et persistance.** Les magasins du lanceur et des projets ont été comparés à `JSONPersistence`. Deux écritures simultanées et des fichiers illisibles ont été reproduits avec les vraies classes ; les cinq magasins utilisent désormais une transaction. Les opérations explicites signalent leurs erreurs.
4. **Analyse statique et architecture.** SwiftLint a parcouru les sources avec cinq règles ciblées ; 33 signaux ont été relus. Une hypothèse de code mort était fausse : la compilation l'a révélé et le code a été rétabli. Les conversions de compteurs du classement ont été vérifiées et corrigées. Aucun gain de performance n'est annoncé sans mesure.
5. **Variantes et revue.** Une revue indépendante a identifié quatre points complémentaires ; leurs corrections ont été testées. La recherche de variantes a aussi trouvé le remplacement des tâches d'automatisation. Une nouvelle revue et la validation finale portent sur la dernière révision figée.

Les révisions numérotées du moteur incluent des points de contrôle supplémentaires pour conserver les tests avant correction et l'essai de suppression annulé. Elles ne représentent pas des passages supplémentaires.

Le manifeste sélectionne les fichiers non ignorés présents à l'initialisation, hors anciens répertoires d'audit. Les nouveaux fichiers de code et de test ont été ajoutés ensuite à l'inventaire, mais le moteur conserve sa sélection initiale : une analyse Semgrep complémentaire explicite a été exécutée sur ces quatre nouveaux fichiers, sans signal. Les outils parcourent le périmètre selon leurs règles et langages effectifs. Les compilations couvrent les cibles Swift et les tests compilés. Les lectures manuelles approfondies portent surtout sur les chemins indiqués dans `contexte.md`, `variantes-workflow.md`, `variantes-valeurs.md`, `variantes-persistance.md` et `controle-swift.md`. Tous les comportements de chacun des quelque 64 000 lignes Swift et toutes les spécifications historiques n'ont pas été examinés manuellement. Un passage d'outil et un test réussi ne prouvent pas une couverture totale.

Les tests Swift omettent les suites `Audit022R4LotT6Tests` et `Spec088ScriptRunnerTests` à cause de leurs signaux forcés ou signaux envoyés à un groupe de processus. `Settings027IPCTests` est omise car elle publie une notification système globale. La suite restante est lancée avec `--no-parallel`. Le premier essai concurrent a échoué sur le délai du socket ; le test a réussi seul et la suite séquentielle a ensuite réussi. Les tests de scripts utilisent des commandes simulées.

La machine n'a pas fourni de surface native à CUA : `CUA_REPL_ENABLED_SURFACES is required`. Aucun parcours graphique du binaire corrigé n'a donc été enregistré. Le protocole n'autorise aucun déploiement ni installation automatiques. Les tests de code ne remplacent pas cette preuve visuelle.

Les scripts de workflow sont une capacité voulue et tournent avec les droits de l'utilisateur ; aucun isolement de code tiers n'est démontré. Le scan d'historique est borné à `v0.4.0` selon la décision antérieure : les commits plus anciens ne sont pas vérifiés. Aucun outil ne prouve l'absence générale de vulnérabilités.
