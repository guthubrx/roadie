# Complément à la revue de la préparation d'intégration

Le complément examine la combinaison préparée avec la branche principale locale `a16c3bcf0391d356d8b67ec7e42f38006df51235`. La fusion se trouve dans un worktree isolé et n'est pas terminée. Les cinq cycles et la décision V15 de l'audit initial ne sont pas modifiés par cette note.

- La sauvegarde de projet est asynchrone. Elle renvoie immédiatement `changed: false` avec le message `project save scheduled`. Un événement `project.saved` suit l'écriture, et `project.save_failed` ainsi qu'une notification signalent un échec. Les lots actuels n'acceptent pas le verbe `saveProject`, et les macros examinées emploient des actions de clic distinctes. Le faux échec redouté sur ces deux parcours n'a donc pas été établi. Le code de sortie de la CLI confirme seulement la mise en file.
- Les tests de stockage vérifient déjà les erreurs de corruption pour l'historique, les alias et les projets, en préservant les octets. Deux tests supplémentaires vérifient que la CLI refuse l'effacement de l'historique si le fichier est corrompu ou si le verrou ne peut pas être créé. Ils vérifient aussi qu'aucun succès n'est annoncé. Les notifications de sauvegarde ou de suppression de projet n'ont pas été testées de bout en bout.
- L'émetteur injectable est utilisé aussi pour le collage ⌘V. Un presse-papiers injectable permet de vérifier la copie et les deux événements du collage sans agir sur le système. Un test vérifie aussi la touche obtenue par le repli sur le caractère et le refus d'un code hors plage.
- Un test vérifie qu'un dossier de remplacement laissé par une interruption reste masqué dans l'index et conservé lors de l'installation suivante. Aucune récupération ou suppression automatique n'est démontrée. Une interruption entre les échanges `Tasks` et `LICENSE` peut toujours laisser une installation partielle.
- Sur ce Mac, le répertoire temporaire utilisé pour les tests d'échange et le dossier réel des workflows sont sur le même volume. Les échanges réels réussissent dans les dossiers temporaires. La compatibilité avec d'autres volumes n'est pas établie.
- Trois archives artificielles ont été extraites dans un dossier temporaire isolé avec `ditto` : une entrée `../outside/sentinel`, un lien symbolique suivi d'une entrée sous ce lien, et un lien seul. Le fichier témoin extérieur est resté intact ; le deuxième cas a échoué à l'extraction ; le lien seul a été conservé. Ces essais ne constituent pas une qualification générale des archives ou des liens symboliques.
- Les commandes `workflow install` et `workflow remove` ne sont pas routées vers le démon par le client CLI ; le serveur rejette aussi les commandes non routées. La boîte de commandes étudiée ne propose pas `workflow`. Le gel du fil principal du démon par le verrou n'est donc pas établi pour ces parcours.
- Une suppression de workflow absent crée le répertoire parent et le fichier de verrou. Cette écriture est un effet secondaire ; ne pas ajouter un contrôle préalable non verrouillé qui réintroduirait une course avec une installation concurrente.
